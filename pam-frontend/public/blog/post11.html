R2 도메인 정리부터

피카밈의 이미지 원본은 Cloudflare R2에 저장돼 있어요. R2 버킷을 만들면 기본으로 pub-xxx.r2.dev라는 개발용 공개 URL이 생기거든요. 이 주소로도 이미지에 접근할 수 있지만, Cloudflare의 성능 최적화 기능들이 적용되지 않더라고요.

가장 먼저 한 일은 이 주소를 비활성화하고 커스텀 도메인 img.pick-a-me.me로 단일화한 것이었어요. 연관해서 DB에 저장된 기존 URL도 마이그레이션(V13, V14)으로 일괄 교체했고요. 여기까지는 실제로 적용돼 있는 내용입니다.

Polish를 켰다고 썼는데

이 글의 원래 버전은 여기서 Cloudflare Polish(Lossy)를 켜서 PNG/JPEG를 WebP로 자동 변환했고, 그 결과 이미지 전송 크기가 절반 가까이 줄었다고 썼었습니다.

그런데 문서 전체를 실제 설정과 대조하는 점검 과정에서 다시 열어보니, Cloudflare 대시보드의 Speed → Optimization → Polish 메뉴가 Pro 플랜($20/월) 이상에서만 켜지더라고요. 피카밈은 지금도 Free 플랜으로 운영 중이라, Polish는 처음부터 켜진 적이 없었습니다.

정정합니다. Polish로 이미지를 WebP로 바꿨다는 부분과, 그로 인해 크기가 줄었다는 수치는 사실이 아니었습니다. 대시보드에서 옵션을 눌러본 기억과 실제로 적용된 상태를 헷갈린 채로 글을 썼더라고요.

실제로 설정된 것들

Polish를 뺀 나머지는 실제로 남아있는 설정이에요. /images/* 경로에 캐시 규칙을 적용했습니다.

1
Caching → Cache Rules → /images/* Edge TTL 1개월 설정
한번 업로드된 밈 이미지는 수정되지 않거든요. 1개월 유지해도 다른 문제가 없고요. Browser Cache TTL은 1일로 별도 설정했어요.
2
Smart Tiered Cache 활성화
상위 티어 엣지 노드가 하위 티어의 캐시 미스를 흡수합니다. R2 ↔ Cloudflare 네트워크 간 egress 무료 정책과는 별개로, 원본(R2) 왕복 횟수를 줄여주는 역할이에요.

R2 egress 비용이 0원인 건 Cloudflare의 정책 덕분이에요. Cloudflare 네트워크 간 트래픽(R2 → Cloudflare CDN)에는 egress 요금이 없습니다. 이건 플랜과 무관하게 적용되는 부분이라, Free 플랜에서도 그대로 유효하고요.

그래서 뭐가 줄었나

포맷 변환이 없었으니 이미지 파일 크기 자체는 그대로예요. 원래 글에 있던 "PNG 320KB → WebP 148KB" 같은 비교표는 실제로 측정한 적 없는 수치라 통째로 지웠습니다.

대신 실제로 바뀐 건 캐시 계층이에요. Edge TTL과 Smart Tiered Cache 덕분에 같은 이미지를 반복 요청할 때 R2 원본까지 왕복하는 빈도가 줄어들거든요. 다만 이것도 정확한 수치로 측정해둔 게 없어서, "체감상 반복 로딩이 빠르다" 이상으로는 말씀드리기 어렵습니다.

왜 이런 일이 생겼나

대시보드에서 Polish 메뉴를 눌러본 기억은 있었거든요. 다만 그게 "옵션을 확인했다"였는지 "실제로 활성화했다"였는지를 구분하지 않고 글을 썼던 것 같아요. Free 플랜에서는 버튼 자체가 비활성 상태로 표시되니, 눌러본 기억이 활성화한 기억으로 뒤바뀐 셈이고요.

이번 정정은 제가 먼저 알아챈 게 아니라, 프로젝트 문서 전체를 실제 코드·설정과 대조하는 점검을 하다가 나온 결과예요. 블로그도 그 점검 대상에 포함되어 있었고요.

이번에 다시 챙긴 것

운영 설정을 글로 옮길 때는 "만져봤다"와 "적용됐다"를 구분해서 써야 하더라고요. 특히 유료 플랜 게이트가 걸린 기능은 대시보드에 메뉴 자체는 보이는 경우가 많아서, 클릭 가능 여부를 실제로 확인하지 않으면 착각하기 쉽거든요.
