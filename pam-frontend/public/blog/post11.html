R2 도메인 정리부터

피카밈의 이미지 원본은 Cloudflare R2에 저장된다. R2 버킷을 만들면 기본으로 pub-xxx.r2.dev라는 개발용 공개 URL이 생긴다. 이 주소로도 이미지에 접근할 수 있지만, Cloudflare의 성능 최적화 기능들이 적용되지 않는다.

가장 먼저 한 일은 이 주소를 비활성화하고 커스텀 도메인 img.pick-a-me.me로 단일화한 것이다. 연관해서 DB에 저장된 기존 URL도 마이그레이션(V13, V14)으로 일괄 교체했다. 이후의 모든 CDN 설정은 커스텀 도메인에서만 작동한다.

Polish — Cloudflare가 이미지를 다시 인코딩한다

Cloudflare Polish는 원본 이미지를 클라이언트가 지원하는 최적 포맷으로 자동 변환해서 전달하는 기능이다. Lossy 모드에서는 PNG/JPEG를 WebP 또는 AVIF로 변환하면서 시각적 품질 저하를 최소화한 채 파일 크기를 줄인다.

작동 방식은 단순하다. 브라우저가 이미지를 요청할 때 Accept 헤더에 지원하는 포맷 목록을 보낸다. Cloudflare 엣지가 이 헤더를 읽어 WebP나 AVIF를 지원한다고 판단하면, 원본 PNG/JPEG를 그 포맷으로 변환한 결과를 캐시하고 응답한다. 원본 파일 자체는 변경되지 않는다.

Cloudflare 대시보드에서 Speed → Optimization → Polish → Lossy 클릭 하나로 활성화된다. 코드 변경 없이 즉시 적용된다. 단, 활성화 직후 기존 캐시에는 구형 포맷이 남아 있으므로 전체 캐시 퍼지(Purge Everything)를 실행해야 즉시 반영된다.

캐시 규칙과 TTL

Polish가 변환한 이미지가 제대로 캐시되려면 캐시 규칙이 맞아야 한다. /images/* 경로에 다음 규칙을 적용했다.

Edge TTL을 1개월로 설정한 것은 밈 이미지의 특성 때문이다. 한번 업로드된 이미지는 수정되지 않는다. 캐시 무효화 없이 오래 유지해도 일관성 문제가 없다. Smart Tiered Cache도 함께 활성화해서 상위 티어 엣지 노드가 하위 티어의 캐시 미스를 흡수하도록 했다.

R2 egress 비용이 0원인 이유는 Cloudflare의 정책 때문이다. Cloudflare 네트워크 간 트래픽(R2 → Cloudflare CDN)에는 egress 요금이 없다. 커스텀 도메인을 통해 제공되는 이미지는 Cloudflare 네트워크 안에서만 이동하므로 실질적인 스토리지 외 비용이 발생하지 않는다.

결과

같은 이미지를 구형 브라우저(PNG 응답)와 최신 크롬(WebP 응답)에서 비교하면 전송 크기가 40~60% 줄어드는 것을 확인할 수 있다. 피카밈에서 사용하는 밈 이미지는 대부분 PNG로 업로드되어 있어서 WebP 변환 효과가 특히 크다.

왜 코드가 필요 없었나

이 최적화가 코드 없이 가능했던 이유는 피카밈의 이미지 구조 덕분이다. 이미지 URL이 CDN 도메인(img.pick-a-me.me)을 통해 제공되므로, CDN 레이어에서 포맷 변환을 투명하게 처리할 수 있다.

만약 이미지를 백엔드 API를 통해 프록시해서 제공하는 구조였다면 이야기가 달랐다. 변환 로직을 직접 구현하거나, Puppeteer나 Sharp 같은 이미지 처리 라이브러리를 도입해야 했을 것이다. 이미지를 CDN에서 직접 제공하는 구조가 이 최적화를 공짜로 가져다 준 것이다.

설계 단계에서 이미지 URL을 CDN 도메인으로 단일화한 결정이, 나중에 Polish 최적화를 도구 변경 없이 적용할 수 있게 만들었다. 좋은 아키텍처 결정은 나중에 무료 점심을 가져다 준다.

이 경험에서 배운 것

인프라 계층의 최적화는 애플리케이션 코드를 건드리지 않고 적용할 수 있는 경우가 많다. 단, 이 경우는 아키텍처가 CDN을 정상적으로 활용하는 구조여야 한다는 전제가 있었다.

비용과 성능을 함께 개선할 수 있는 기회가 있다면, 코드 복잡도를 높이기 전에 인프라 레이어를 먼저 확인하는 것이 빠를 때가 있다.
